Chart data are in `frontend/static/data/charts/*.json` and on the website at
`/data/charts/<file>.json`. They are generated by `pathogensportal-db`; they are not edited by hand,
because the next processing run would overwrite the changes.

## Structure

```json
{
  "labels": ["KT 40/26", "KT 41/26"],
  "labels_en": ["Wk 40/26", "Wk 41/26"],
  "datasets": [
    { "label": "Influenza A (celkem)", "label_en": "Influenza A (total)", "data": [1, 4] }
  ],
  "meta": { "chart_id": "flu_weekly", "metric": "lab_detections", "unit": "count", "…": "…" }
}
```

| Field | Meaning |
|---|---|
| `labels` | labels of the X axis (periods, age groups, regions…) |
| `datasets[]` | series: `label` and the values `data` in the same order as `labels` |
| `*_en` | English versions of the labels (`labels_en`, `label_en`, `x_title_en`, `unit_en`) |
| `x_title`, `unit` | title of the X axis and the unit (on some charts) |

The website ignores colours and series styles in the file; it uses its own palette.

## Metadata `meta`

| Field | Meaning |
|---|---|
| `chart_id` | chart identifier |
| `metric`, `unit` | what is measured and in which unit |
| `grain` | time granularity (`week`, `month`, `year`…) |
| `region` | territorial granularity (`CZ`, `NUTS3`…) |
| `generated_at` | when the file was created (UTC) |
| `period` | the period covered (`start`, `end`, number of points), where available |
| `source_ids`, `sources[]` | sources: publisher, page, licence, when the data were downloaded |
| `caveats[]` | known limitations and breaks in the data (`id`, `since`, `description`, `impact`) |

The Signals output (`anomaly_signals.json`) has its own structure: the month evaluated
(`target_period`), the list of signals and the method parameters (`provenance`).
